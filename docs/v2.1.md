One mobile system across every route: restrained surfaces, clear type, shared spacing,
large primary actions, comfortable forms and immediate feedback. Keep the official
UNEEM identity, English/Arabic, account authority and booking rules intact.

## Audit findings

- AuthShell overrides all theme colors and forces dark, unlike the rest of the app.
- TextField derives IDs from translated labels, uses 15px text and premature validation.
- Toast positions itself fixed inside a second fixed container, creating overlap;
  its close button does not notify the store, and two timers control its lifetime.
- Mobile spacing uses multiple gutter/padding owners and ignores visual viewport changes.
- Announcement state exists only inside the notification page, leaving badges stale elsewhere.
- First render waits on external Google font CSS; topbar downloads an 820KB torch for 28px.
- Existing shared controls still use different borders, heights, focus and pressed feedback.

Use existing Svelte/Tailwind/Lucide/Playwright tooling. Browser skill is unavailable,

where authenticated accounts are unavailable; fixture checks are not hosted E2E proof.

### Batch 1: shared UI and auth

Implemented shared button/link variants, 44px minimum targets, 56px primary form
actions, semantic field labels/IDs, calmer surfaces, self-hosted fonts, light/dark auth,
native dialogs, keyboard viewport handling, and stacked/dismissible top-layer toasts.
Login includes a full-width secondary Create account button. Registration headers
no longer overlap Back. Forms wait for hydration to prevent lost input/native submits.

The original brand vector now has an opaque background and a larger, mask-safe mark.
Regenerated 180/192/512px PNG exports replace the inconsistent installed app icons.
Topbar now uses the 3KB vector instead of the 820KB torch. Removed the blocking Google
stylesheet. Geist is served locally (29KB); Noto Sans Arabic loads for Arabic UI.
Mobile auth content starts below the header without vertical recentering. Forgot
password sits next to its field label; primary and secondary actions are grouped.

Local dependencies required a lockfile reinstall to restore missing Windows bindings.
Type checking reached zero errors/warnings. Production build passed. Visual checks:
390x844 English/Arabic, 320x420 short viewport, 1440x960 desktop; no overflow or page errors.
Tested password visibility, empty-form validation, independent toast dismissal/stacking,
and simulated visual-viewport keyboard state. This does not certify a physical iPhone.

Corrected two existing test-fixture mistakes: exact matching for the obsolete Ready
badge (instead of matching Already), and exposing the Auth API version header so the
Supabase SDK can read the mocked error code. No auth authority checks were relaxed.

Verification checkpoint: all 32 existing public smoke cases passed in a single run
after the font/position refinement. Targeted checks also cover the subsequent inert
shell during hydration, toast dismissal and keyboard simulation. Remaining routes,
notification behavior and production/physical-device gates are still open.
